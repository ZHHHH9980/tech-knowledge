# 架构评估自检清单

## 输入证据与交互

- [ ] 是否判断本方案是否影响用户可见页面或交互
- [ ] 适用时是否实际读取相关 Figma 页面、节点、原型连线和注释，而非只看截图
- [ ] 不适用时是否记录“Figma 不适用”及理由
- [ ] Figma 缺失或无法访问时，是否将方案完整性标记为证据不足
- [ ] 是否覆盖主路径、loading、空态、成功、失败、重试、取消和重复操作
- [ ] 是否将关键交互映射到接口、字段、状态所有者、后端副作用及幂等/并发规则
- [ ] 是否显式列出 PRD、Figma、Tech Design、接口定义和现有实现之间的冲突与待确认决策

## 问题定义

- [ ] 是否明确了当前状态、目标状态与非目标
- [ ] 是否写清楚了核心矛盾，而不是实现细节
- [ ] 是否说明了组织与协作约束

## 方案比较

- [ ] 是否至少比较了 2 个可行方案
- [ ] 评估维度是否一致且可对比
- [ ] 是否给出事实依据（数据/依赖图/历史事件）

## 决策质量

- [ ] 是否写明为何选中该方案
- [ ] 是否显式写出 trade-off
- [ ] 是否记录了被否定方案的参考价值

## 落地可执行性

- [ ] 是否有分阶段迁移计划
- [ ] 是否定义了兼容策略和回滚策略
- [ ] 是否有可量化的 Done Definition
- [ ] 用户交互验收是否能追溯到具体 Figma 页面/节点、动作、状态和用户可见结果

## 风险控制

- [ ] 是否识别了高风险点
- [ ] 是否有对应缓解动作与兜底方案
- [ ] 是否有灰度和观测指标
