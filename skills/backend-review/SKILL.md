# BE 后端评审

本技能整理已有后端结构、Go 可读性、消费点覆盖与 ID 精度规则。默认只读，不因评审而修改代码或发布；按用户给定的范围选用模块，不把所有专项强制执行一遍。

## 选择已有检查模块

| 用户任务或改动证据 | 读取材料 | 交付 |
|---|---|---|
| 结构、职责、规则分叉、状态所有权、隐藏副作用或配置发布依赖 | [结构评审](references/structure.md) | 结构发现、配置发布依赖状态 |
| Go 类型、命名、参数、interface/any、控制流与注释可读性 | [Go 专项](references/go-readability.md)，结合结构评审边界 | Go 可读性发现；与结构模块同根因合并 |
| 共享凭证、端点、client、开关、配置发生变化 | [消费点与 ID 专项](references/dependency-and-identifiers.md)的消费点覆盖模式 | 消费点覆盖矩阵 |
| ID 跨 JSON、JWT、JavaScript 或其他弱类型边界 | 同一专项中的标识符精度模式 | 标识符往返链路和完整性矩阵 |

泛化的后端 Review 先确认实际变更和用户关注点，再使用适用模块；报告明确实际检查了哪些维度，不将专项检查通过表述为完整代码审查通过。

## 基线与证据

- 基线优先级：用户指定 → PR/MR 目标 → upstream 或远端默认分支。读取足够的调用者和上下文。
- 区分已提交、暂存、未暂存和未跟踪改动，明确实际覆盖范围。
- 只报告本次新增或明显加剧的问题；纯移动、重命名按语义比较。
- 消费点检查沿定义处枚举完整调用链，不只看 diff 中出现的消费者。
- 跨 JavaScript 的标识符检查继续覆盖实际消费链，不因 FE/BE 分类而截断证据。

## 输出

先给结论和适用模块，再列文件行号、证据、受影响路径、具体建议与未知项。同一根因只报告一次。结构模块沿用 P1/P2，消费点和 ID 专项沿用其风险级别，并说明实际影响，不将不同量表名称混为同一门禁。

遵循项目的验证约定；没有验证的行为或容量结论标为未知，不新增与本次任务无关的检查能力。
